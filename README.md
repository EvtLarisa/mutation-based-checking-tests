# mutation-based-checking-tests

Программа экспериментов с мутационными проверяющими тестами для компонентов последовательной
автоматной сети на случайно сгенерированных автоматах к статье «Исследование мутационных проверяющих
тестов для компонентов автоматных сетей» (журнал «Информационные технологии»): дополнительная серия
экспериментов из п. 3.1 и эксперименты с трансляцией теста из п. 3.2.

Связанные репозитории:

- генератор случайных автоматов - https://github.com/EvtLarisa/fsm-generation;
- эксперименты с генератором широтно-импульсной модуляции (ШИМ) - https://github.com/EvtLarisa/generator.

## Постановка

Рассматривается бинарная последовательная композиция A∙B: внешние входы I подаются только на головную
компоненту A, ее выход (внутренний канал U) является входом хвостовой компоненты B, наблюдается только
выход B (канал O). Проверяется компонента B. Мутационный тест строится по автомату-композиции
Spec = A∙B, поэтому подается на внешние входы сети и не требует трансляции через контекст.

Пары автоматов строятся тем же алгоритмом и от тех же зерен, что и в генераторе fsm-generation
(функция `rand_fsm` в `fsmnet.py`), поэтому автоматы каждой пары можно получить и посмотреть отдельно.

## Установка

Нужен Python 3.8 или новее и библиотека `networkx` (проверено на версии 3.7).

```bash
git clone https://github.com/EvtLarisa/mutation-based-checking-tests.git
cd mutation-based-checking-tests
pip install -r requirements.txt
```

Все команды ниже запускаются из корня репозитория.

## Порядок запуска

```bash
python exp_random.py          # 1. дополнительная серия, около минуты
python exp_translation.py     # 2. серия с трансляцией, около 20 секунд
python report.py              # 3. сводка результатов
```

Программы 1 и 2 перезаписывают файлы в папке `results` (получаются те же значения). Другой файл
результатов и число параллельных процессов можно указать так:
`python exp_random.py my_results.json -j 4`; справка - `python exp_random.py --help`.
Сводку по другим файлам можно получить командой `python report.py папка_с_результатами`.

## 1. Дополнительная серия экспериментов (п. 3.1), `exp_random.py`

Пары: p = 2, 3, 4 и N = K = 3, 5, ..., 15 - по 20 пар; при p = 2 еще 5 пар для N = K = 20 и 30 и по
3 пары для N = K = 40 и 50; всего 436 пар. Для каждой пары строятся два теста:

- MB1 - обход графа переходов Spec (кратчайший обход всех переходов со сбросами, задача китайского
  почтальона), дополненный кратчайшими различающими последовательностями для еще не обнаруженных
  мутантов B первого порядка с ошибками переходов;
- MBC - покрытие только тех переходов B, которые используются в композиции, дополненное тем же
  способом.

Полнота обоих тестов проверяется относительно всех обнаружимых через контекст мутантов первого
порядка (ошибки переходов и выходов) и случайной выборки до 1000 обнаружимых мутантов второго порядка.
Длина теста - сумма длин последовательностей плюс один символ сброса на каждую последовательность.

Поля записи в `results/random_436.json` (одна запись на пару):

| Поле | Значение |
|---|---|
| `N`, `K`, `p`, `seed` | параметры пары и зерно |
| `r` | число достижимых состояний Spec = A∙B |
| `reachB`, `used` | число состояний B, достижимых в композиции, и число используемых переходов B |
| `nRT`, `unreachB`, `unusedU`, `masked` | число мутантов первого порядка с ошибками переходов и число необнаружимых среди них: на недостижимых в композиции состояниях B, на неиспользуемых входах, замаскированных контекстом |
| `n1` | число обнаружимых мутантов первого порядка (переходы и выходы) |
| `tour`, `MB1`, `cover`, `MBC` | длины обхода, теста MB1, покрытия и теста MBC |
| `MB1_added`, `MBC_added` | сколько различающих последовательностей добавлено |
| `MB1_M1`, `MBC_M1` | доля обнаруженных мутантов первого порядка |
| `n2`, `MB1_2nd`, `MBC_2nd` | размер выборки мутантов второго порядка и доля обнаруженных |
| `time` | время счета пары, с |

## 2. Трансляция теста изолированной компоненты (п. 3.2), `exp_translation.py`

Пары: p = 2, N = K = 2..15; p = 3, N = K = 3..15; p = 4, N = K = 3..10; по 10 пар; всего 350.
Для каждой пары строится тест компоненты B как независимого автомата: W-тест (граница числа состояний K)
при N = K <= 4, иначе MB12 автомата B (обход графа переходов B, дополненный различающими
последовательностями для мутантов B первого и второго порядка). Каждая последовательность теста
транслируется через A: до B доходит наибольший префикс, который A может породить из начального
состояния. Затем полнота транслированного теста сравнивается с полнотой теста MB1, построенного по Spec,
на обнаружимых мутантах первого (все), второго и третьего (выборки до 1000) порядков.

Поля записи в `results/translation_350.json`:

| Поле | Значение |
|---|---|
| `N`, `p`, `k`, `seed` | параметры пары, ее номер и зерно |
| `kind` | вид теста изолированной B: `W` или `MB12` |
| `r` | число достижимых состояний Spec |
| `iso_len`, `iso_cnt` | длина и число последовательностей теста изолированной B |
| `tt_len`, `MB1_len` | длины транслированного теста и теста MB1 |
| `seq`, `sym` | доля последовательностей, транслируемых целиком, и доля символов, доходящих до B |
| `n1`, `n2`, `n3` | число обнаружимых мутантов первого, второго, третьего порядков |
| `TT1`..`TT3`, `MB1_1`..`MB1_3` | сколько из них обнаруживают транслированный тест и MB1 |

## Воспроизводимость

Все случайные автоматы и выборки мутантов строятся от фиксированных зерен, поэтому повторный запуск
дает те же результаты (кроме поля `time`). Обход графа переходов строится с помощью `networkx`; при
другой версии библиотеки порядок последовательностей обхода может отличаться, что может немного
изменить длины тестов MB1 и MB12.
